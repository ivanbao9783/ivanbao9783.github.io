# Badcase 复盘方法论 SOP

> 目标：把评测跑出的**单个失败样本**，加工成**可跨数据集复用的经验资产**——一份结构化复盘报告 + 融合进模式卡的证据 + 按需发布的博文。
> 本 SOP 只规定**方法论与流程**；写作规格见 `_TEMPLATE.md`（①–⑩ 报告结构），类型判定见 `_TAXONOMY.md`，各模式完整方法论见 `cards/`，案例索引与投射表见 `README.md`。
> few-shot 范例（线上博文）：[确定性全零](https://ivanbao9783.github.io/posts/automationbench-deterministic-zero/)、[推理档退化](https://ivanbao9783.github.io/posts/automationbench-effort-regression/)。

## 一、核心立场

Badcase 不是"这道题错了"的统计，而是**高信息量的信号源**。同一批失败样本，从三层视角看出去是三种产出：

| 视角 | 产出 | 归入报告节 |
|---|---|---|
| 数据集设计层 | 题面歧义 / 判分器误杀漏放 / 覆盖不足 | ⑧ |
| 模型训推层 | 能力边界 / 系统性短板 | ⑨ |
| Agent harness 层 | 工具接口 / 循环预算 / 上下文脚手架缺陷 | ⑩ |

**三条硬规矩**：
1. **绝对量化**——步数、分数、Token、占比，能用数字就不用形容词；
2. **先证据、后归因**——每条归因必须能指回证据链；
3. **上升到一类问题**——报告要产出可迁移规律，而非复述个案。

## 二、角色与文件

| 文件 | 角色 | 何时用 |
|---|---|---|
| `SOP.md`（本文件） | 方法论主控（M0–M7 能力流水线、卡点、中间件约定） | 每次 |
| `_TEMPLATE.md` | 单案报告模板（①–⑩） | M1–M4 |

| `cards/*.md` | 5 张模式卡（识别 / 还原 / 资产 / 归因 / 修复 / 案例） | M4–M5 |
| `README.md` | 案例索引 + 案例→模式卡投射表 | M4–M5 |

## 三、方法论总览（能力流水线）

```
M0 采集与去噪 → M1 还原失败现场【卡点1】 → M2 核心资产抽取 → M3 归因分层
→ M4 类型归档（多标签投射到 5 张模式卡）【卡点2】 → M5 融合沉淀 → M6 发布与集成 → M7 回归验证
```

八个能力，前四个是"把个案讲清楚"，后四个是"把个案变成资产"：

| 阶段 | 能力 | 一句话 |
|---|---|---|
| M0 | 采集与去噪 | 从评测产物里挑出**值得复盘**的样本 |
| M1 | **还原失败现场** | 从 trace/终态/日志**逆推"当时发生了什么"** |
| M2 | **核心资产抽取** | 从个案里抽出**可复用之物** |
| M3 | 归因分层 | 按模型 / harness / 数据 / 采样四层定位主因 |
| M4 | 类型归档 | **多标签**投射到 5 张模式卡 |
| M5 | 融合沉淀 | 把证据写进模式卡，形成"一卡多例" |
| M6 | 发布与集成 | 博文 + 星图 + 落地页三件套 |
| M7 | 回归验证 | 修复后纳入回归集，闭环 |

## 四、中间件管理（全流程适用）

- 中间件一律以 markdown 落盘到 `tmp_workspace/badcase-analysis/<slug>/`，**禁止把中间件全文打在聊天框里**；
- 命名：`00_intake.md`（M0）/ `01_reconstruct.md`（M1）/ `02_assets.md`（M2）/ `03_report.md`（M3–M4，套 `_TEMPLATE.md`）；
- 聊天框只出现：一句话摘要 + 文件路径 + 卡点选项；
- M6 定稿后删除 `tmp_workspace/badcase-analysis/<slug>/`，临时区不残留。

## 五、M0 · 采集与去噪

**挑出"值得复盘"的样本**——不是所有失败都值得深挖。优先采样四类信号：

| 信号 | 判据 | 对应模式 |
|---|---|---|
| 跨配置稳定失败 | 换配置仍错 → 排除随机性 | 确定性全零型 |
| 高分近失 | 分数 0.9+ 却未过线 | 近失完备性型 |
| 稳定撞限 | 多配置都撞步数上限 | 结构性预算型 |
| 二值翻转 / 反常波动 | 同任务 0↔1、方差高 | 全有全无翻转型 |
| 配置相对退化 | 换配置后某类任务变差 | 配置退化型 |

> **单断言任务**是最佳切入口：断言只有 1 条却失败，排查成本最低、指向最明确。

## 六、M1 · 还原失败现场【卡点 1】

**目标**：从原始产物逆推"模型当时到底做了什么、卡在哪、终态如何"。这是整条方法论的**可信度地基**——没有现场还原，归因就是猜测。

**输入**：评测 trace / 工具调用序列 / 世界终态（end_state）/ 日志 / 断言逐条结果。

**动作**（四步倒放）：

1. **对齐断言**：逐条列出断言及其过/不过，标注缺失项；
2. **回放动作序列**：按轮次重建"读 → 算 → 写 → 验"的动作链，定位中断点；
3. **提取终态快照**：抓最后一条动作/输出，判断是"执行/提交"还是"读取/验证"被截断；
4. **算量化指纹**：轮次、工具调用总数、调用每轮（密度）、步数/上限、输入输出 Token、翻转率/方差。

**产出**：`01_reconstruct.md`——一张"关键节点 | 观测值 | 说明"的证据链表 + 终态快照。

**各模式的还原要点**见对应模式卡第 3 节（如配置退化型看"调用密度"、确定性全零型看"措辞 vs 断言逐字比对"）。

**【卡点 1】**：现场还原稿（含证据链表）送用户审——用户确认"现场还原无遗漏、量化数据可信"后才进入 M2。

## 七、M2 · 核心资产抽取

**目标**：从个案现场里抽出**可复用之物**，让一次复盘产出长期资产，而非一次性报告。

**资产分四类**：

| 资产类 | 内容 | 去哪 |
|---|---|---|
| **证据锚点** | 断言原文、调用密度对比、终态快照、Token 膨胀比 | 模式卡「证据锚点」 |
| **识别指纹** | 一眼认出该模式的判据（如"收件人正确 + 断言全败"） | 模式卡「识别特征」 |
| **修复动作** | 数据集 / 模型 / harness 三侧的可执行改法 | 模式卡「修复动作」 |
| **可迁移结论** | 脱离本 case 的规律 + 避坑 Checklist | 报告 ⑦ / 模式卡 |

**抽取纪律**：只抽**能被下一次复用**的东西；一次性的运行细节留在报告里，不塞进卡。

## 八、M3 · 归因分层

**先给因子贡献度排序，再逐层归因**，每条归因回指 M1 证据。四层判据：

| 层级 | 典型归因 | 判据 |
|---|---|---|
| 模型层 | 行为风格改变（并行→串行）、取舍偏差（过度拒绝） | 调用密度/终态风格随配置变 |
| Harness 层 | 预算刚性、工具发现成本高、循环无过渡 | 撞限、单任务调用数畸高 |
| 数据层 | 断言口径过严、任务陷阱、规模超预算 | 措辞与断言粒度鸿沟、注入策略 |
| 采样层 | 温度引入抖动 | 贴边任务跨运行跳变 |

> **区分判据**：数据层问题"换任何模型都错"，模型层问题"换配置即变"，harness 层问题"改脚手架即缓解"。

## 九、M4 · 类型归档（多标签投射到 5 张模式卡）【卡点 2】

**目标**：把案例**投射**到 5 张模式卡上。模式**不互斥**，用**多标签**：一个案例可同时命中多张卡。

**5 张模式卡**（详见 `_TAXONOMY.md` 与 `cards/`）：

| 卡 | 识别指纹 |
|---|---|
| `config-regression` 配置退化型 | 换配置后某类任务分数下降 |
| `near-miss-completeness` 近失完备性型 | 稳定只差极少数断言 |
| `structural-budget` 结构性预算型 | 跨配置稳定撞步数上限 |
| `deterministic-zero` 确定性全零型 | 跨运行稳定 0 分且未撞限 |
| `all-or-nothing-flip` 全有全无翻转型 | 同任务跨运行 0↔1 翻转 |

**归档动作**：
1. 对照 `_TAXONOMY.md` 判定基准，逐卡勾选是否命中（可多选）；
2. 标注**主模式**（主导根因所在卡）与**次模式**；
3. 写入 `README.md` 的「案例 → 模式卡 投射表」；
4. 若均不命中 → 按 `_TAXONOMY.md` 的"待记录模式"命名新卡。

**【卡点 2】**：投射结果（主/次模式勾选）送用户确认——用户可在投射表上直接改标签，确认后才进入 M5。

## 十、M5 · 融合沉淀

**目标**：把 M2 抽出的资产**融合**进对应模式卡，形成"**一卡多例**"的积累结构。

**融合规则**：
- 资产写入**主模式卡**；次模式卡只补一行"关联案例"指针；
- 卡内「证据锚点」按案例累加，保留最小充分证据（断言原文 / 一条密度对比 / 一张终态快照）；
- 若新案例与卡内既有结论**冲突**，先信证据、双标注差异，不静默覆盖；
- 同步更新 `README.md` 索引与类型统计。

## 十一、M6 · 发布与集成

按需把复盘稿升级为线上博文（保留 ①–⑩ 结构化报告体），完成三件套：

1. **博文**：`_posts/YYYY-MM-DD-<slug>.md`，`categories: [评分与诊断]`，tags 含 `Badcase`；日期须早于实际推送时间（防 Jekyll 跳过未来日期）。
2. **星图登记**：`_data/starmap.yml` 的 `scoring.badcase` 节点 `posts:` 追加文件名；节点 `status` 随篇数升级（≥1 篇 seeded，≥2 篇 deep）。
3. **落地页**：若主题超出 `_domains/scoring/badcase.md` 现有版图，同步更新其"代表工作 / 内容规划"。

推送后走 CI（Pages Deploy）验证 → 线上抽查（博文 200、落地页聚合数 +1）。

## 十二、M7 · 回归验证（闭环）

修复动作落地后，把该案例纳入**回归集**：
- 数据集侧修复 → 用原 case 复跑，验证确定性零分/坏断言是否消失；
- harness 侧修复 → 对比修复前后撞限数、调用密度；
- 结果回写模式卡「修复动作」小节（标注"已验证 / 待验证"），方法论闭环。

## 十三、失败处理

| 情况 | 处理 |
|---|---|
| 无 trace，仅有终态 | M1 降级为"终态反推"，只出终态快照 + 断言差分，标注"动作序列未捕获" |
| 断言不可见（黑盒） | M4 靠现象指纹归档，报告 ⑧ 标注"断言口径未核验" |
| 跨配置仍未复现 | 归为**采样噪声**，不进模式库，只在附注记录 |
| 单案例证据不足判主模式 | 标"待定"，暂挂多张卡，累积到第二个同类案例再定 |
| 无官方图源 | 报告默认文字 + 表格，不强制配图 |
