# 模式卡 · 结构性预算型（Structural Budget）

> 类型 ID：`structural-budget` · 常见严重度：P1 · 判定基准：跨配置稳定撞步数上限，任务规模**超出预算**（换模型 / 换配置也一样）。

## 1. 识别特征

- 多次运行都撞步数上限，且**与配置无关**——换推理档、换模型仍撞限。
- 表现为"N 步内做不完"：任务的动作规模本身就大于预算。
- 与"配置退化型"区别：后者的撞限是配置诱发；本模式的撞限是**任务固有**的。

## 2. 判定基准（准入条件）

同时满足：
1. 同一任务在**多个配置 / 多个模型**下都撞限；
2. 任务的动作规模（最小可行步数）> 预算上限；
3. 失败与随机性无关，属确定性不可解。

## 3. 现场还原要点（M1）

该模式的现场还原核心是**撞限的跨配置稳定性 + 规模-预算缺口**：

| 观测面 | 抓什么 | 说明 |
|---|---|---|
| 撞限稳定性 | 各配置下是否都撞限 | 区分"结构性"与"配置诱发" |
| 步数证据 | 步数 == 上限 | 撞限的直接证据 |
| 规模估算 | 任务最小可行步数 vs 上限 | 量化"差多少步" |
| 失败分布 | 撞限任务中失败占比 | 撞限是否必然导致失败 |

## 4. 核心资产抽取清单（M2）

- **跨配置撞限任务清单**
- **规模-预算缺口表**（每任务最小可行步数 vs 上限）
- **预算敏感度分级**（贴边 / 中位 / 远超）
- **不可解任务标记**

## 5. 归因指纹（M3）

典型层级分布：**数据层 / harness 层（任务规模超预算）为主**，模型层次要。

- 数据层：任务设计规模超出评测预算；
- harness 层：步数上限刚性、无过渡机制。

## 6. 修复动作（三侧）

- **数据集侧**：拆分超长编排链，或标注为"高压预算任务"并在榜单口径中单列。
- **模型侧**：提升单位步数的动作效率（减少无效探索）。
- **harness 侧**：按任务类型设差异化上限；提供元工具发现，把预算留给业务动作。

## 7. 证据锚点（融合自案例）

- 结构性预算案例：13 个任务两档都撞 50 步上限、12 个失败；任务规模超出预算，对任何模型都不可解。→ `tmp_workspace/badcase-blog/`（原稿）

## 8. 关联模式（多标签）

- **配置退化型**：配置提升会把原本不撞限的任务推成撞限（次模式）。
- **全有全无翻转型**：贴边撞限任务重复运行会出现 0↔1 翻转。
