# 数据集介绍博文生成工作流 SOP

> 目标：输入一个 AI/Agent 数据集的基本信息，产出符合范式的知乎/掘金风格技术博文（含截图预埋位与截图任务清单），并按范式第九节完成仓库集成四件套。
> 核心写作规格：`数据集介绍博文大纲范式.md`（下称"范式"），本 SOP 不重复其内容，只规定流程。
> few-shot 范例（线上博文）：[AutomationBench](https://ivanbao9783.github.io/posts/automation-bench/)（业务模拟型）、[ALE](https://ivanbao9783.github.io/posts/ale-agents-last-exam/)（真实环境交付型）、[DeepSWE](https://ivanbao9783.github.io/posts/deepswe/)（代码真实仓库型）。

## 角色与文件

| 文件 | 角色 | 何时用 |
| --- | --- | --- |
| `SOP.md`（本文件） | 流程主控 | 每次 |
| `数据集介绍博文大纲范式.md` | 写作规格（六层结构、资产策略、校准清单、仓库集成规范） | P3–P6 |
| `input_template.md` | 运行入口，用户填写 | P0 |
| `research_checklist.md` | 调研动作清单（论文/官网/榜单/仓库各抓什么） | P1 |
| `fact_sheet_template.md` | 事实登记表（防幻觉核心） | P2 |
| 三篇线上范例博文 | few-shot 对照 | P3–P5 |

## 流程总览

```
P0 输入收集【卡点 0a：输入确认】 → P0.5 类型预判确认【卡点 0】 → P1 四路调研 → P2 事实表【卡点1】
→ P3 类型判别+大纲 → 【卡点2：hook/case/概念稿】 → P4 成文 → P4.5 用户整读【卡点3 · 大中断】
→ P5 自检 → P6 仓库集成四件套
```

## 中间件管理（全流程适用）

- 工作流中间件（输入登记、事实表、大纲）一律以 markdown 文件落盘到 `tmp_workspace/dataset-blog/<slug>/`，**禁止把中间件全文打在聊天框里**
- 聊天框只出现：一句话摘要 + 文件路径链接 + 卡点交互选项；卡点送审方式 = 用户在 IDE 打开文件审 + 交互框确认
- 文件命名：`00_input.md`（P0）/ `01_fact_sheet.md`（P2）/ `02_outline.md`（P3）
- P6 定稿后统一删除 `tmp_workspace/dataset-blog/<slug>/` 整个目录，临时工作区不残留

## P0 · 输入收集【卡点 0a：输入确认】

用户按 `input_template.md` 提供：数据集名、论文地址（含版本锚定）、官网、leaderboard、（可选）代码仓库、（可选）Artificial Analysis 榜单地址、口径要求（平台/字数/时效锚定日/主推角度/对比豁免）。

**用户消息中输入字段不全时（常见：只给一个数据集名），必须走输入确认交互，禁止静默采用 Agent 自己猜的地址**：

1. Agent 按已知信息预填草稿，每个 URL 标注"预填，待确认"
2. **单独交互框**向用户逐项请求确认 / 修正 / 补充——必须包含选填的 `aa_leaderboard_url`（Artificial Analysis 榜单：无官网或官方榜单易失真的数据集，它是榜单数据的第一校准源；用户填写则 P1 榜单路以它为最高优先级）
3. 用户确认后才能进 P0.5；预填地址即使被确认，P1 仍要逐路核实
4. 用户明确说"由你调研补全"时，缺失维度按原规则处理：照常启动，P2 事实表标明"该维度无官方来源"，不用二手数据顶替

> 来源：MMLU-Pro 实战复盘（2026-09-24）。用户只给名字时 Agent 预填地址直跑，侥幸全对，但输入权责应归属用户——数据集存在重名/同名续作/镜像站，预填错地址会把整轮调研带偏；且 HF 数据集页嵌入的榜单 widget 与官方榜单本体存在数据滞后（当日即翻车：widget 显示 89.5，实际榜首已 91.16），AA 地址必须由用户决定是否提供。

## P0.5 · 类型预判确认【卡点 0】

输入收齐后，先做一次数据集类型预判（评测基准 / 训练集 / 语料库 / 混合体），连同判断依据（评测对象是什么、裁决靠什么）向用户确认，**确认后才进 P1**。

来源：DeepSWE 模拟复盘中，初始把评测基准误判为训练集问题，导致调研方向一度跑偏。类型判错，P1 调研重点和 P3 专有件全错——这道卡点值得前置。

## P1 · 并行调研

按 `research_checklist.md` 执行，四路并行 + 一路轻量线索：

1. **论文**：摘要、主结果表、失败/误差分析节、任务构造节、评分机制节、附录的任务卡样例（abs 页只有摘要时需进 PDF 全文）
2. **官网**：首屏统计数字、规模口径、出品方
3. **Leaderboard**：榜单来源优先级——**用户填写的 AA 榜单（`aa_leaderboard_url`）最高** > 官方榜单本体 > SPA 数据端点 > 官方页面嵌入的派生 widget（常滞后，只作参考）> 第三方聚合。官方榜单先直接抓页面；若是 SPA 只返回壳，从页面 JS chunk 里找数据端点（如 `/api/xxx/leaderboard`）拉原始数据
4. **代码仓库**（若有）：挖 1-2 个 task 卡原文（题面 + 评分代码），供第④层单题深挖
5. **社区线索**（轻量，可选）：作者宣传帖 / Reddit / X 讨论——只作第⑥层批判的观点线索，**其中的数字一律不进事实表**（守住一手来源原则）

**工具能力假设**：第 3 路需要能拿原始 HTML/JS 的抓取能力（markdown 转换会丢 script 标签）；第 4 路需要能读 GitHub 文件树。运行前确认 Agent 工具链满足，不满足时降级方案见"失败处理"。

## P2 · 事实登记【卡点 1】

将全部候选数字填入 `fact_sheet_template.md`，每行必须含：数字 | 出处（论文表号/页面/端点）| 抓取日期 | 口径备注 | 原文摘录。

硬规则：
- 博文成文时出现的每个数字，必须能在事实表里找到对应行，找不到就删或补调研
- 事实表逐行登记抓取日期，论文/官网/榜单来源各自注明（正文标注方式见 P5：开头统一声明官方数据截取时间即可，论文数据为固定版本无需逐处标注）
- **矛盾处理**：论文 / 官网 / 榜单数字打架时，采信优先级为 论文 > 官网 > 榜单；正文引用时双标注差异（"论文 v2 为 X，官网现为 Y"），不静默取舍
- **原文摘录**：关键数字把源文本片段粘进事实表（轻量快照）——防止源页面/端点后续改版导致无法复核
- 事实表写入 `tmp_workspace/dataset-blog/<slug>/01_fact_sheet.md`；聊天框只给文件路径 + 一句话摘要（行数、矛盾点、覆盖检查结论），用户在 IDE 审完后经交互框确认，**确认后才进入 P3**

## P3 · 类型判别 + 大纲

1. 回答范式第三节的判别问题（评测对象/裁决方式/题目来源/物理成本），判出数据集类型；范式专有件对照表是**示例参照，不是查表抄写**——新数据集按判别答案逐槽派生，类型不在表内时按主导维度归类并在大纲里注明
2. 产出大纲：标题（含 hook 候选 2-3 个，候选可融合——结构取一版、金句取另一版，融合变体一并送审）、六层各层的素材分配、case 选题（优先官方门面案例，否则说明理由）、📸 预埋位规划
3. 官方图源不足 4 张时：按范式第五节自绘两段式流程产出 **mermaid 概念稿**，与大纲一并送审
4. 大纲（含类型判别、hook 候选、case 选题、📸 规划）写入 `tmp_workspace/dataset-blog/<slug>/02_outline.md`；聊天框只给文件路径 + 一句话摘要
5. **【卡点 2】用户（在 IDE 审阅大纲文件后）选定 hook、case、（若有）mermaid 概念稿**后才动笔

## P4 · 成文

- 按范式六层结构 + 字数占比成文，专有件按 P3 判别结果填
- 截图一律预埋（📸 + 编号 + 来源 + 裁剪范围 + 图注），不代截
- 概念稿通过的自绘图：用 Excalidraw 画终稿，同样只预埋引用不导出；**生成后必查元素文字居中与完整展示**（Excalidraw 绑定文本常见不居中/溢出截断，导入画布肉眼核验后再定稿）
- 数字只从事实表取
- 全篇不引入横向对比（独立解耦原则，除非官方素材/用户输入明确要求）

## P4.5 · 用户整读【卡点 3 · 大中断】

第一版全文产出后，交用户整体审视——格式、内容、行文风格全面过一遍，**用户放行后才进入 P5**。

- 这是全流程最大的中断点：用户会提出各类问题和修改意见，预计多轮"修改 → 复审"迭代，不要指望一次过
- 修改意见分流处理：格式问题直接改；涉及数字/事实的改动必须回事实表核对（事实表同步更新）；行文风格按用户意见调整
- 每轮只改用户点名的部分，不顺手重写未点名段落——避免引入新问题

## P5 · 自检

逐项跑范式第八节校准清单（含 4-5 张图、呼吸感、独立解耦三项新检查），附加检查：
- [ ] 全文数字与事实表逐一对上
- [ ] 草稿数字不在事实表时：回源二次抓取验证 → 属实则补录事实表（含原文摘录与二次抓取日期）→ 不实则删改；禁止"看起来对"就放行
- [ ] 正文开头统一声明官方数据（官网/榜单）截取时间；论文数据为固定版本，无需逐处标注
- [ ] 每个机制小节"论断 + 证据"两件套
- [ ] 引用的任务卡/数据原文与数据集 license 兼容（license 未标注时正文不整段转载原文，只摘要转述）
- [ ] Excalidraw 自绘图：元素内文字居中且完整展示（无溢出/截断）
- [ ] 图注无 AI 痕迹（按范式 9.2 硬性检查项：无"一张图说清/一图交代/自绘说明/诚实备注"等元叙述）
- [ ] 结尾停在批判 + 可带走设计（默认无对比表、无金句）

## P6 · 交付（仓库集成四件套）

按范式第九节执行：

1. **博文文件**：`_posts/YYYY-MM-DD-<slug>.md`，front matter 按 9.1 模板（含 tags/categories/description）
2. **截图任务清单**：每个 📸 位 + .excalidraw 位列出"来源页面/图源 → 截取范围 → 存成 `assets/img/<文章slug>/<前缀>_<序号>_<说明>.png`"；用户补图/导出后核对图注与实际内容一致
3. **starmap.yml 登记补丁**：指出博文应加入哪个节点的 `posts:`（数据集介绍类默认 corpus，按 9.3 判别）
4. **落地页内容提示**：所有节点页均已含「领域定义/核心价值/知识版图与规划」总览；若博文主题超出该节点现有版图描述，提示站长同步更新该页总览
5. **中间件清理**：定稿后统一删除 `tmp_workspace/dataset-blog/<slug>/` 整个目录（00_input / 01_fact_sheet / 02_outline），临时工作区不残留

用户补图并确认后，走 9.4 集成自检 → push → CI 验证 → 线上抽查，定稿。

## 失败处理

| 情况 | 处理 |
| --- | --- |
| 论文无失败模式数据 | 第⑤层降级为"出题设计经济学"归因，不编造失败数据 |
| leaderboard 不可访问 | 第②层"当前水平"用论文主结果表，标注时效 |
| 无代码仓库 | 第④层用论文附录任务卡；再无则用官方门面案例页 |
| case 找不到题面原文 | 换 case，四拍结构缺题面原文就不成立 |
| Agent 无原始 HTML 抓取能力（SPA 榜单拉不动） | 第②层改用论文主结果表 + 官网静态数字，榜单数据留空并标注"未实时核验"；不引用二手转载 |
| 论文只有 abs 页无 PDF | 主结果表缺失时降级为官网数字为主，事实表标明"论文全文未核验" |
