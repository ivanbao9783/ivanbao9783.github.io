# 调研清单（P1 阶段逐项执行）

## 一、论文（优先级最高的证据源）

- [ ] 摘要：规模、SOTA 水平、出题方
- [ ] 主结果表：各档/各配置的 pass rate 与 mean score，**注意运行口径**（几次平均、best-of-N）
- [ ] 失败模式/误差分析节：官方失败分类及占比（Hook 与第⑤层的首选素材）
- [ ] 任务构造节：题目从哪来、过什么筛选（第③层机制一素材）
- [ ] 评分机制节：评分模式清单（断言/测试/对 reference/judge，第③层机制二素材）
- [ ] 附录任务卡样例（第④层 case 候选）
- [ ] 领域分布图 / 评测管线架构图（📸 预埋候选，论文原图优先）
- [ ] **锚定版本**：记录本次引用的 arXiv 版本号（如 v2），与 input 的 paper_version 一致

## 二、官网

- [ ] 首屏统计数字区（规模/专家数/覆盖面）
- [ ] 私有集与公开集的规模和用途
- [ ] living benchmark 状态（目标规模、增长中？）

## 三、Leaderboard

- [ ] 先直接抓页面；SPA 壳页面 → 从 JS chunk 找数据端点拉原始数据
- [ ] 各档 Top1 配置与分数（区分 tier 口径）
- [ ] 榜单计分口径（best-of-N？与论文主表是否一致？）
- [ ] 记录抓取日期

## 四、HF 数据集卡（若有 hf_url）

- [ ] 字段结构（features/schema）、splits 划分与各 split 规模
- [ ] license（第④层任务卡原文引用的合规边界）
- [ ] 加载代码 / 数据生成脚本位置（可作第③层机制证据）
- [ ] 下载量/likes（第⑥层社区接受度线索，标注为非论文证据）

## 五、代码仓库（若有 repo_url）

- [ ] 找 1-2 个信息最全的 task 卡/任务定义文件，读题面原文 + 评分代码
- [ ] 选 case 标准：官方门面案例 > 陷阱最多的中等难度题 > 最难题
- [ ] task 卡能提供的：题面、输入数据结构、评分断言原文、硬门条件

## 六、社区线索（轻量、可选，不进事实表）

- [ ] 作者宣传帖 / Reddit / X 上的一手讨论——只作第⑥层批判的观点线索与盲区候选
- [ ] **硬规则：社区来源的数字一律不进事实表**（一手来源原则），确需引用时正文标注"社区传闻，未经核验"

## 停止条件

以上五路覆盖了六层结构的全部素材槽位即可停止；不追求把仓库读完。每拿到一个数字先记入事实表（带出处），不在调研阶段写正文。

**图源盘点（离场前清点）**：可用官方图（论文 Figure/官网图/榜单截图）不足 4 张时，标记缺口并触发范式第五节自绘两段式流程（P3 产出 mermaid 概念稿）。
