## 1. 背景与目标

站长是 LLM & Agent 评测领域的开发工程师，希望将个人主页从「博文流」重构为「领域知识地图」形态。核心目的：

1. **固化学习资产**：把在该领域的学习过程沉淀为结构化知识，并通过清晰的全景与脉络，识别自己欠缺的领域知识（缺口可视化）。
2. **支撑可复用工作流**：领域地图结构化后，可作为后续 Agent 工作流的输入/输出接口，提升领域学习效率。

### 已确认的关键决策（脑暴结论）

| 决策点 | 结论 | 备注 |
|---|---|---|

| 落地页形态 | 混合（C）：四段式骨架 + 未完成降级 | 骨架全量建好，进度本身即缺口可视化 |

## 3. 信息架构

```
ivanbao.github.io
├─ /                     ★ 星图首页（新）
├─ /domains/{一级}/{二级}/  ★ 领域落地页（新，15~25 个）
├─ /archives/            博文流（从首页迁入，复用现有 home.html 布局）
├─ /tabs/about/          关于（保留）
├─ /tabs/tags/           标签（保留）
└─ /tabs/categories/     分类（保留或并入「文章」入口，实施时定）
```

**导航 Tab**：知识星图（/）· 文章（/archives/）· 标签 · 关于

**双向可达**：
- 正向：首页星图 → 点击节点 → 落地页 → 博文
- 逆向：博文页底部「所属领域」链接 → 落地页 → 「返回星图」

### 首页（星图）

- 星图占满首屏，无 hero 文案区、无博文卡片，保留顶部导航栏
- 视觉编码（图例常驻角落）：
  - **虚线椭圆** = 星团边界（一级子域）
  - **节点大小** = 内容量（博文数/覆盖度，数据驱动）
  - **实心不透明** = 已有积累；**半透明** = 规划中（缺口是一等公民）
- 悬停：tooltip（领域名 + 文章数 + 一句话简介）
- 点击：直接跳转落地页（不做图内下钻）
- 团间连线：仅真实跨域关系，带语义分类

### 领域落地页（/domains/…）

- 面包屑：知识星图 / {一级星团} / {二级领域}，附「返回星图」
- 四段式骨架（front matter 配置驱动，段落标题可自定义）：
  1. **概述**（手写）：解决什么问题、边界、核心矛盾
  2. **核心概念**（手写）：术语卡片/对比表/mermaid 图
  3. **学习路径**（手写，标题可改，如「方法选型指南」「论文清单」）：推荐阅读顺序
  4. **相关博文**（自动聚合）：按数据文件的归属关系自动列出
- **降级机制**：某子域尚未整理时，落地页自动降级为「纯博文聚合 + 整理中标记」；写完概述后升级为完整 Wiki 页。骨架全量建好（15~25 页），完成度本身即目的 1 的可视化。

## 4. 数据模型（单一事实源）

一个 YAML 数据文件（建议 `_data/starmap.yml`）驱动整站：

```yaml
clusters:                      # 一级子域 = 星团
  - id: eval-system
    title: 评测系统
    color: "#5e87b0"           # 主题内可被令牌覆盖
    children:                  # 二级节点 + 晋升的工具节点
      - id: harness
        title: 评测框架
        status: deep           # deep | seeded | planned
        url: /domains/eval-system/harness/
      - id: harbor             # 明星工具晋升节点
        title: Harbor
        status: deep
        parent: harness        # 归属二级域（博文聚合仍按 parent）
        url: /domains/eval-system/harness/  # 未独立成页时可指向父页
edges:                         # 团间/节点间连线，手工维护
  - from: dataset.compression
    to: eval-system.ci
    type: cost                 # 语义分类，如 cost / method / evolution
```

- **status 三态**：`deep`（已深耕）/ `seeded`（有内容）/ `planned`（规划中）→ 映射为视觉透明度
- **晋升规则**：某工具 ≥2 篇博文或深度实践 → 从「落地页聚合项」晋升为「图谱节点」

## 5. 视觉设计

### 默认主题：羊皮纸地图（B）

- 米色纸纹底 + 点阵网格，带描边实心圆节点，虚线椭圆星团边界
- 气质：大航海时代知识版图 / 学者笔记，与站长 Excalidraw 手绘工作流一脉相承

### 预留主题：深空星云（A）

- 深蓝黑底 + 发光星体 + 柔和光晕 + 星空底噪

### 双主题令牌系统

- 所有视觉差异收敛为主题令牌（背景/纸纹、节点填充/描边、光晕有无、文字色、星团边界样式）
- **构建时切换**：配置字段切换默认主题
- **运行时切换**：页面角落主题开关，SVG class + CSS 变量瞬时换肤，偏好存 localStorage；背景装饰（纸纹/星空）用两层背景按主题显隐

### 布局稳定性

- **固定坐标**：不做力导向动画，坐标审阅定稿后写入数据文件，防止布局漂移、建立空间记忆

## 6. 技术方案

- **零依赖**：不引入 ECharts/Cytoscape/D3
- **服务端渲染**：Jekyll 构建时由 Liquid 模板循环 YAML 数据生成静态 SVG（圆/椭圆/贝塞尔曲线/文本）
- **浏览器端 JS 约 100 行**：tooltip、hover 高亮、点击跳转、主题切换
- **SEO 友好**：SVG 内文本可被索引
- **移动端降级**：星图为桌面主打体验；移动端提供目录树降级视图（实现阶段细化：可按屏幕宽度阈值切换，或 SVG viewBox 缩放 + 平移手势，取实现成本低者）
- **性能**：静态 SVG 数 KB，无运行时图库开销
