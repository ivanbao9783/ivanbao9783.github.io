## 领域定义

裁判体系是评测的「判卷者」学：把 LLM-as-Judge 从一段 prompt 做成可信的生产组件。涵盖判分边界的划分（判定唯一 → 代码断言，存在分歧空间 → 模型代判）、Rubric 的原子化与可判定化、偏差的分层归因与测量、与人工参照物的一致性对账、多裁判的选型与聚合，以及上线后的版本治理与对抗兜底。

## 核心价值

裁判是开放式产出唯一的规模化判分手段——确定性断言守得住格式与红线，守不住"答得对不对、好不好"。但裁判本身是一个带偏差的概率组件：不给它失败的定义，它就会自补一个默认刻度（"读起来像不像好答案"），于是分数漂亮而问题照旧。裁判体系的价值就在于让这把尺子可解释、可校准、可治理。

## 知识版图与规划

**关键问题**：判分边界的唯一性判据；Rubric 与需求的一一对应；偏差住在 prompt 层 / 模型偏好层 / 权重层的哪一层；一致率与 κ 的正确读法；聚合的收益与成本边界；换裁判等于换尺子的版本可比性。

**代表工作**：Hamel Husain 的三层 eval、Anthropic 的 grader 分类学、Arize 的人机对齐 field guide、JudgeBiasBench 与 Judging the Judges 等去偏研究。

**内容规划**：`judge-01`~`judge-09` 九篇子系列（先定义失败 → 划判分边界 → rubric 可判定化 → 偏差分层 → 一致性统计与校准 → 裁判选型与聚合 → 线上治理与对抗），执行中。相邻领域见 **Rubric 与指标设计**（判卷标准的通用写法）与 **评测范式**（判分方式随范式的演进）。
